# v0.6.16 — Other mods' victory remarks and timer names

Released October 29, 2026. It removes two installation stops caused by other mods,
in components 290 and 265, on top of v0.6.15. The installer still exposes
**49 declarations in seven groups**.

## Player behavior

- **290 — victory remarks that other mods add.** After the battle of Avernus, the
  companions present remark on the victory one after another (`BD4300`), and 290
  shortens the pause after each remark to 2 seconds so that the celebration goes
  on in time. It expected exactly the 17 vanilla remarks plus Aura's. Sirene NPC
  for BG:EE adds one for Sirene in the same shape, so 290 stopped the
  installation ("expected 17 vanilla timer setters plus zero/one exact C0Aura
  block; found 18 setters"). 290 now checks the shape of every block that sets
  the remarks' timer, whoever added it, and shortens all of them. Aura is no
  longer a special case, and everything else in these blocks, the remarks
  included, stays as it was. A timer setter outside such a block, a remark with
  two setters, any other way of writing the timer and a script without any
  remark still stop the installation before anything is written.
- **265 and six more components — timer names from the game's own table.**
  WeiDU prints a decompiled timer with the name that the game's `GTIMES.IDS`
  gives its value. Dark Tidings adds `60 ONE_TURN` to that table, so Shadow
  Aspect's 60-second summon timer then reads `ONE_TURN` instead of `TEN_ROUNDS`,
  and 265 refused the unchanged summon block ("HARDEST summon block differs from
  the original/corrected contract"). 265 now asks WeiDU which name this game
  prints for 60 seconds; the rest of its exact check is unchanged. **135, 140,
  200, 245, 256 and 266** matched their own timers by the vanilla name too and
  now read the name the same way, so a mod that names 6, 10, 12, 18 or 30
  seconds differently no longer stops them. 200 and 245 write their new
  30-second parley timer as the number 30, which compiles to the same script as
  `FIVE_ROUNDS`.
- Nothing else changes.

## Install timing and limits

- Unchanged from v0.6.15.
- An existing installation needs no update. Where these components installed
  before, they install the same result now.
- **290 does not play `bdcut61`.** Its direct ending goes from the celebration
  to Shadows of Amn without SoD's farewell cutscene, so additions that other
  mods make to that cutscene do not run either. With Sirene NPC for BG:EE, her
  own farewell does not run: she stays in the party to the end, and the ending
  banks her SoD gear in EET's invisible import chest like the rest of the
  party's. Sirene NPC for BG2:EE then brings the same Sirene back in Shadows of
  Amn with new gear, so her old gear, a second copy of her sword included, stays
  out of reach in that chest. Nothing changes for now; see
  [#37](https://github.com/Chrizhermann/chriz-sod-rebalance/issues/37).

## Verification boundary

- Regression tests with real WeiDU in synthetic games:
  - 290: a `BD4300` with the 17 vanilla remarks, with Aura's, with Sirene's,
    with both, with one vanilla remark removed, with a single remark, with an
    already shortened script and more. The patched script is compared byte for
    byte with a separately compiled one in which every remark waits 2 seconds.
    Every refused shape stops with nothing written or backed up.
  - Timer names: the game's own `GTIMES.IDS`, the same after Dark Tidings'
    addition, tab-separated variants and another mod's name for a value. 265
    installs under each of them, and with the game's own table every
    component's result is byte-identical to v0.6.15's.
- Lab on a disposable EET 2.7.3.0 copy of the full Chriz Easy BG Recommended
  stack with Sirene NPC for BG:EE added, from a release candidate with the same
  mod files as this release. It installed without errors. 290 installed as
  v0.6.16, and 292 and 910 installed too. The installed `BD4300` has 18 remarks,
  17 vanilla ones plus Sirene's; all 18 now wait 2 seconds, and Sirene's own
  actions in her block are unchanged.
- In that game, the chapter, the plot state, the start of the celebration
  cutscene and two moves within `BD4300` were set through the console, next to
  de Lancie (the walk to her got stuck in the crowd) and next to Dazzo. The rest
  ran natively: Sirene's remark fired, the celebration went on, de Lancie's talk
  followed, and Dazzo's talk ended SoD. Shadows of Amn's opening played to the
  end, with Imoen joining. Sirene NPC for BG2:EE brought Sirene back with her
  BG1 and SoD experience, kit and portrait, and a save census found exactly one
  Sirene.
- The ending's contract script (`verify_ending.py --platform eet`) on that
  installed game: 41 checks pass and 2 fail. Both failures are frozen
  expectations of the script, not faults of the ending: Sirene's script roots
  at the end of the plot, and the blocks that 292 adds to the ending's carrier
  script. Tracked in
  [#36](https://github.com/Chrizhermann/chriz-sod-rebalance/issues/36).
- Not covered: a lab install with Dark Tidings and a playthrough of the Shadow
  Aspect fight, a playthrough of the battle of Avernus itself, and standalone
  BG:EE+SoD with Sirene NPC for BG:EE.
- Local run on the release source (Windows, WeiDU 249): 441 regression tests
  pass (8 skipped where a captured fixture or the development game copy is not
  available), as do the 41 research-script tests and the ending self-test's 14
  checks. WeiDU 249 parses the TP2 and all 75 TPA libraries.
